# 可用脚本

`package.json` 文件包含一组 npm 脚本，用于简化常见的开发任务。这些脚本有助于构建、测试、代码检查和部署应用程序。它们可以通过 `npm run <script-name>` 命令在项目根目录下执行。

以下是每个可用脚本的详细参考。

### 核心开发与代码质量

这些脚本对日常开发工作流程至关重要，从编译代码到确保其质量。

| 脚本 | 描述 |
|---|---|
| `build` | 使用 esbuild 将 `src` 目录中的 TypeScript 源代码编译为 JavaScript，并将结果输出到 `dist` 目录。 |
| `build:watch` | 以观察模式运行构建过程。每当源文件发生更改时，它会自动重新编译代码。 |
| `debug` | 使用 Node.js 直接执行已编译的 CLI 应用程序。这对于在本地测试构建后的版本很有用。 |
| `test` | 使用 Jest 运行整个测试套件，以验证应用程序的功能。 |
| `coverage` | 执行测试套件并生成代码覆盖率报告，显示代码库被测试覆盖的程度。 |
| `lint` | 使用 ESLint 分析 TypeScript 源代码，检查代码风格问题和潜在错误。 |
| `lint:fix` | 运行 linter 并自动修复所有可自动修复的问题。 |
| `verify` | 一个便捷脚本，按顺序运行 linter 和测试套件。这对于在提交代码前进行最终检查很有用。 |
| `clean` | 删除 `dist` 目录，移除所有先前编译的文件和构建产物。 |

### 部署与版本管理

这些脚本用于部署应用程序和管理其版本号。

| 脚本 | 描述 |
|---|---|
| `deploy` | 执行本地全局安装。它会构建项目，卸载 `to-where-cli` 的任何现有全局版本，然后全局安装当前的本地版本。这对于本地构建的端到端测试非常理想。 |
| `deploy:remote` | 从 npm 注册表重新安装 `to-where-cli` 的最新发布版本。这对于从本地开发版本切换回正式发布版本很有用。 |
| `bump-version` | 使用 `ver-bump` 工具增加 `package.json` 中的包版本号。 |
| `show:version` | 显示当前在 npm 上发布的 `to-where-cli` 包的最新版本号。 |

### 实用工具

| 脚本 | 描述 |
|---|---|
| `reinstall` | 删除 `node_modules` 目录并使用 `pnpm` 重新安装所有项目依赖。这有助于解决与依赖相关的问题。 |
